## 项目背景与问题定义

古代技术典籍中的机械图像往往散落于不同书籍、版本、卷页和版式中。研究者不仅需要查找“外形相似”的图，还需要判断图示结构、文字说明、功能描述与关系结构是否值得比较。单纯以图像相似度排序，容易把“形似而功能不同”的图排在前列，也容易把模型推测误表述为历史事实。

“机图索隐”面向这一问题，建设一个证据感知的古代技术图像关联检索系统。系统通过文本、整图和局部区域三种入口召回候选，再综合视觉、文本、区域、功能与关系信息进行 EAFR 重排序，并把来源、证据类型、不确定性和人工核验状态与结果一并呈现。

当前 V1 的定位是可复现的工程基线：

- 证明“数据导入 → 目录浏览 → 三类检索 → EAFR 重排序 → 证据查看 → 人工核验持久化”可以闭环运行。
- 采用确定性离线 Provider，确保无外网、无大模型时仍可演示。
- 不声称已完成真实古籍 OCR、真实语义理解或历史传承判定。

## 术语

| 术语 | 定义 |
|---|---|
| Book | 古籍或技术文献的作品级记录 |
| Edition | 某一书籍的具体版本、刊刻或数字化来源 |
| Page | 版本中的卷页、页叶或扫描页 |
| Figure | 页面内可独立分析的技术图像单元 |
| Region | Figure 内的局部结构区域，使用归一化坐标描述 |
| TextChunk | 与页面或图相关的图题、正文、OCR 原文或人工校订文本片段 |
| CFR | Concept–Function Representation，概念—功能表示；当前 V1 为规则多标签基线 |
| EAFR | Evidence-Aware Fusion and Reranking，证据感知融合与重排序 |
| Provider | 文本、图像、CFR、关系等能力的可替换实现，必须报告模型与版本元数据 |
| Provenance | 资源来源与处理链信息，包括书籍、版本、卷页、URL、哈希、许可和流水线版本 |
| Evidence | 支撑候选关联的图像、文本、元数据或关系证据 |
| Observed | 可直接从图像或资源中观察到的内容 |
| Documented | 文献正文、图题或已明确记录的内容 |
| Inferred | 由规则或模型推断、尚未经人工确认的内容 |
| Verified | 经授权人员基于可回溯证据确认的内容 |
| AssociationCandidate | 某次查询产生的候选关联及其排名、分项得分和核验状态 |
| SearchSession | 一次搜索的查询类型、查询摘要、配置、模型版本、耗时和候选集合 |
| Fixture | 为测试而生成的可复现小型示例数据，不代表真实研究样本 |
| 困难负例 | 外形相似但功能不同，用于检验排序是否过度依赖视觉外形的样本 |

## 用户与职责

| 角色 | 核心诉求 | V1 权限边界 |
|---|---|---|
| 研究浏览者 | 浏览古籍目录，发起检索，查看证据和来源 | V1 无登录，受控环境内可调用公开 V1 接口 |
| 核验人员 | 判断候选是否值得比较并记录理由 | V1 与浏览者没有技术权限隔离；角色仅表示业务职责 |
| 数据整理人员 | 准备 manifest、资源、文本、关系与许可信息 | 仅能通过配置目录中的受控 manifest 发起导入 |
| 系统运维者 | 启动数据库和服务，执行迁移，检查健康和日志 | 管理 Docker、本地配置和数据目录；凭据不进入仓库或日志 |
| 前端客户端 | 按 OpenAPI 调用后端并正确展示证据状态 | 不得改变证据语义，不得使用“AI 证明传承”等误导措辞 |
| 文史或技术史专家 | 提供真实资料校订、功能标注和研究判断 | 当前 V1 没有专家账号或审批流，正式流程属于后续版本 |

V1 不提供身份认证、授权和多租户能力。因此上述角色是业务角色，不是系统访问控制角色。服务只能部署在本地或明确受控的演示网络中。

## 核心业务流程

### 数据进入系统

~~~text
数据整理人员准备受控 manifest
  → 系统校验 manifest 名称、路径、字段、文件、哈希和许可
  → 写入书籍、版本、页面、图、区域、文本、功能断言、关系和证据
  → 离线 Provider 生成向量及版本元数据
  → IngestionJob 记录完成状态、统计或错误
~~~

### 研究检索闭环

~~~text
浏览目录或准备查询
  → 发起文本 / 整图 / 局部区域检索
  → 多模态基线召回数据库候选
  → EAFR 计算分项、证据覆盖与不确定性并重排
  → 返回来源、候选图、匹配区域、证据和模型版本
  → 用户打开候选详情与许可允许的资源
  → 用户提交人工核验状态与备注
  → 重启服务后仍可读取核验结果
~~~

### OCR 后续流程

~~~text
真实扫描页
  → 版面与阅读顺序分析
  → 竖排、繁体、异体字 OCR
  → 保存原始识别、坐标、置信度和模型版本
  → 人工逐字校订
  → 原始 OCR 与校订稿并存
  → 进入文本检索、CFR 和证据链
~~~

该 OCR 流程属于计划项。当前 fixture 中的文本是预置数据，不是 OCR 输出。

### 数据导入

| 需求编号 | 状态 | 优先级 | 需求说明 | 验收要点 |

| FR-013 | 已实现 | P0 | manifest 只能从配置的数据目录按文件名解析，必须拒绝绝对路径、父目录跳转、符号链接逃逸或未登记文件。 | 路径穿越测试失败且不访问数据根外文件。 |

| FR-018 | 已实现 | P0 | IngestionJob 应记录 manifest、流水线版本、起止时间、逐类统计和错误摘要。 | completed 有统计；failed 有安全、可读且不泄露服务器路径或密钥的错误。 |

## 业务规则

| 规则编号 | 规则 |
|---|---|
| BR-001 | 系统输出的是“候选关联”和“值得比较的线索”，不是历史传承、影响关系或源流的自动证明。 |
| BR-002 | synthetic fixture 的结果只能用于接口、数据链和稳定性验证；论文、答辩和展示必须标记 not_evaluated。 |
| BR-003 | Observed、Documented、Inferred、Verified 是证据语义，不是从低到高自动晋级的模型置信度。 |
| BR-004 | Candidate 的 verified 与 Evidence 的 Verified 相互独立；核验候选不得批量改写底层证据。 |
| BR-005 | 来源不完整、哈希不匹配或许可不明确的数据不得进入可公开再分发状态。 |
| BR-006 | allow_training 和 allow_redistribution 是两个独立许可决策；允许展示不等于允许训练，允许训练不等于允许公开原图。 |
| BR-007 | 资源响应必须同时通过数据库许可检查和文件系统路径边界检查。 |
| BR-008 | manifest 输入是受控文件名，不是通用服务器文件读取接口。 |
| BR-009 | page_id 与 figure_id 在区域查询中严格二选一。 |
| BR-010 | query 长度为 1—1000，top_k 范围为 1—50；服务端不接受 NaN 或 Infinity 坐标。 |
| BR-011 | EAFR 权重由 `SearchService` 构造函数设置并支持代码级注入，运行值会写入搜索会话配置；当前尚未暴露为环境变量或管理 API，且只属于 baseline，不得描述为训练得到的最优权重。 |
| BR-012 | 缺失模态和模型不确定性必须分开记录，缺失不能伪装为模型低置信。 |
| BR-013 | 只有达到阈值的图内关系三元组可参与 sg；跨图关系由候选关联表达。 |
| BR-014 | 数据库不可用时必须显式失败，不得静默切换 SQLite 或静态 JSON。 |
| BR-015 | 当前确定性 Provider 是工程基线，不具备可宣称的真实古籍语义理解能力。 |
| BR-016 | OCR 原始结果在人工核对前属于机器推断层；人工校订必须保留原文和修改轨迹。 |
| BR-017 | 无登录的 V1 不得部署到开放互联网或承载需要用户隔离的数据。 |
| BR-018 | 前端不得使用“史实概率”“AI 证明传承”“已证实源流”等超出证据范围的措辞。 |

## 状态模型

### 导入任务状态

| 当前状态 | 可进入状态 | 触发条件 | 说明 |
|---|---|---|---|
| queued | running、failed | Runner 获取任务；或启动前校验失败 | queued 记录已持久化，但当前 Runner 为进程内实现 |
| running | completed、failed | 全部事务与统计完成；或出现不可恢复错误 | 关键写入应遵循事务边界 |
| completed | 无自动转换 | 导入成功 | 对同一 manifest 可创建新的任务，但实体保持幂等 |
| failed | 无自动转换 | 校验、许可、文件或数据库失败 | 修正原因后由用户重新创建任务 |

V1 不提供分布式任务队列、自动重试或崩溃恢复。进程中断时遗留的 queued/running 任务需要运维确认和重新提交，此限制必须写入运行手册。

### 候选核验状态

| 状态 | 语义 | 允许的后续操作 |
|---|---|---|
| 未核验/空值 | 尚无人提交判断；这是展示层初始态，不是 VerificationRequest 的枚举值 | 可提交任一合法核验状态 |
| worth_comparing | 有进一步比较价值，但尚不等于事实结论 | 可改为其他合法状态并更新备注 |
| rejected | 当前证据支持排除该候选 | 可在新增证据后重新核验 |
| disputed | 存在冲突解释或专家意见不一致 | 可在讨论后重新核验 |
| verified | 候选关联已人工确认达到当前核验标准 | 可因新证据重新核验；不改变 Evidence 状态 |
| insufficient_evidence | 当前资料不足以判断 | 可在补充资料后重新核验 |

V1 只保证核验结果持久化和可读取，不承诺多人审批链、不可变审计历史或角色签名；这些属于 V2。

### 证据状态

| 状态 | 来源 | V1 公开接口是否可修改 |
|---|---|---|
| Observed | 图像中可直接观察的结构或属性 | 否 |
| Documented | 来源文献明确写出的内容 | 否 |
| Inferred | 规则或模型推断 | 否 |
| Verified | 已按既定流程人工核验的证据内容 | 否 |

证据状态在 V1 是来源语义标签而非公开状态机。未来若增加证据核验接口，应要求 Inferred 或 Documented 到 Verified 的转换附带核验人、时间、证据引用和版本，且保留原状态历史。

| DR-012 | Verification 保存候选、合法状态、备注与时间；V1 不把候选核验写回 Evidence。 |
| DR-013 | IngestionJob 保存 manifest 名称、queued/running/completed/failed 状态、统计、错误和流水线版本。 |

### Fixture 数据规则

- fixture 必须显式标记 synthetic_fixture。
- fixture 图片应由确定性脚本生成，可通过 SHA-256 复核。
- fixture 中可包含 same_function、related_mechanism 和 similar_form_different_function 标签，仅用于验证业务分支与回归测试。
- fixture benchmark pair 不是训练集、验证集或真实测试集，不得计算并发布真实研究指标。

### 统一错误

错误外壳：

~~~json
{
  "error": {
    "code": "INVALID_QUERY",
    "message": "面向用户的简洁提示",
    "request_id": "uuid",
    "details": {}
  }
}
~~~

| HTTP 状态 | 业务语义 | 规范错误码示例 |
|---:|---|---|
| 403 | 资源许可不允许访问或再分发 | LICENSE_RESTRICTED |
| 404 | 书籍、页面、图、资源、搜索或候选不存在 | RESOURCE_NOT_FOUND |
| 413 | 上传图片超过字节或像素安全限制 | INVALID_IMAGE |
| 422 | 查询、图片、区域来源、坐标、资源路径、manifest 文件名或请求 schema 无效 | INVALID_QUERY、INVALID_IMAGE、INVALID_REGION_SOURCE、COORDINATE_OUT_OF_RANGE、INVALID_ASSET_PATH、INGESTION_INVALID_MANIFEST |
| 503 | 数据库不可用 | DATABASE_UNAVAILABLE |
| 500 | 未预期内部错误 | INTERNAL_ERROR |

错误 details 仅用于提供字段级、可公开的诊断信息，不得返回堆栈、SQL、凭据或数据根绝对路径。

导入接口同步接受任务并返回 202 后，manifest 内容、引用或资源校验失败会写入 `IngestionJob.status=failed` 与受控错误摘要，而不是再产生一条 HTTP 422 响应；HTTP 422 的 `INGESTION_INVALID_MANIFEST` 主要覆盖同步的 manifest 文件名校验。

MODEL_UNAVAILABLE 是真实 OCR 或远程模型接入后的预留错误语义，当前 V1 的离线 Provider 实现不会抛出该错误。当前公开实现也没有需要 409 的业务分支；若后续增加并发状态冲突，必须再定义稳定错误码并补充契约测试。

日志不得记录：

## 安全、许可与伦理要求

- 原始资源访问遵循默认拒绝原则；只有 allow_redistribution=true 且路径安全时才能返回。
- allow_training=false 的资源不得进入模型训练集，即使其允许在本地查看。
- 真实数据接入前必须确认来源机构、权利状态、授权范围、署名方式、再分发限制和撤回流程。
- 文件上传只用于当前请求的特征提取，不把用户上传自动纳入数据集或训练集。
- 模型推断不得覆盖原始文献、OCR 原文、人工校订或 provenance。
- 所有比较结果必须允许用户查看证据来源与不确定性，不能只显示单一“可信度百分比”。
- 比赛展示应明确区分工程演示、模型实验、专家判断和历史结论。

## 版本与优先级规划

### V1 / P0：工程闭环

状态：已实现。

- 目录与受控资源访问。

- 三类检索与确定性 Provider。

- synthetic fixture 与自动化测试。

V1 的交付结论只能是“工程流程已跑通”，不能是“算法对真实古籍有效”。

### V1.1-A / P0：演示可靠性基线

状态：已实现。

- 前端响应在 API 边界执行 Zod 运行时校验，并统一处理契约错误与请求中止。
- 修复三服务健康检查，Compose 重建后 frontend、backend 和 db 均为 healthy。
- 新增全栈 smoke runner，覆盖幂等导入、三类检索、资源许可与核验持久化。
- 新增 3 项 Playwright E2E，通过真实 Nginx、API 和 PostgreSQL 链路验证核心页面流程。
- fixture 继续标记为 `not_evaluated`，本里程碑只提升演示可靠性，不产生算法效果结论。

### V1.1-B / P1：真实数据与 OCR 试点

状态：计划或待评估。

- 选择一批权利状态明确、可合法处理和展示的真实古籍页面。
- 建立版面、文字、图题和局部结构的小规模专家标注规范。
- 接入 PaddleOCR 或经选型确认的 OCR 基线，同时保留可替换 Provider。
- 支持竖排、繁体、异体字、图文混排、低置信字符和人工校订。
- 建立 raw OCR 与 corrected text 双层数据及版本追踪。
- 发布真实 OCR 质量报告，不以 fixture 替代。
- 在冻结的专家标注小样上比较文本、视觉、CFR 和 EAFR baseline。
- 补充性能基准、契约兼容性和任务故障恢复。

### V2 / P2：研究与规模化

状态：计划。

- 接入真实文本、视觉和多模态模型，并保留离线降级能力。
- 基于真实数据做模型训练、消融、困难负例与跨版本泛化评测。
- 在数据规模证明必要后引入 pgvector ANN 索引。
- 增加账号、角色权限、专家工作台、核验历史、审批与审计。
- 增加持久任务队列、重试、取消、并发限流、监控和告警。
- 提供比较视图、标注导出、研究数据版本和可复现实验包。
- 在专家主导下研究跨图关系，但仍不自动宣称历史传承。

## 风险、依赖与待决策项

| 类型 | 内容 | 处理要求 |
|---|---|---|
| 数据许可 | 古籍扫描件的公开访问不等于允许训练或再分发 | 接入前完成逐来源许可清单和证据留存 |
| OCR 难度 | 竖排、繁体、异体字、污损、雕版和图文混排会显著降低通用 OCR 效果 | 先建立真实标注小样，再决定微调或模型替换 |
| 标签一致性 | 功能概念可能受术语时代差异和专家解释影响 | 建立术语表、标注指南、争议状态和一致性测量 |
| 排序偏差 | 视觉外形可能压过功能与证据，或规则词表造成虚假增益 | 使用困难负例、消融、分项校准和专家错误分析 |
| 任务可靠性 | V1 使用进程内后台任务，进程崩溃不具备自动恢复 | 受控演示可接受；真实批量导入前升级任务基础设施 |
| 性能扩展 | 当前 Python 精确余弦适用于 fixture，不代表大规模性能 | 真实规模测量后再选择 ANN 和缓存 |
| 公网风险 | V1 无认证 | 仅本地/受控网络部署，开放部署前完成 V2 安全需求 |

需要在 V1.1-B 启动前确认的事项：

- 首批真实古籍来源、许可范围和可公开展示方式。
- OCR 模型候选、运行硬件、版面标注粒度和字表策略。
- 专家标注规范、核验人资格、争议解决与一致性指标。
- 真实检索基准的查询集合、正负例定义、数据切分和指标。
- 是否在 V1.1 引入持久任务队列，还是继续限制为小规模离线导入。

## 发布与变更原则

- 本文是需求基线，不替代 OpenAPI 的机器可读字段定义；二者冲突时应先确认当前实现，再同步修正文档或代码。
- 任何新增模型都必须通过 Provider 能力声明、版本元数据、可复现实验和降级行为验收。
- 任何真实数据都必须先完成 provenance、许可、哈希和可撤回性检查。
- 任何声称“效果提升”的结论都必须来自冻结的真实测试集，并同时报告基线、样本量、指标定义、误差与失败案例。
- 破坏 V1 客户端的接口变更应进入新的 API 版本，不得在不告知前端的情况下复用字段改变语义。
- 每次发布应更新需求状态、OpenAPI 快照、迁移说明、测试记录和 not_evaluated/已评估边界。
