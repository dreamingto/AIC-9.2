## 检索如何使用模型

文本查询：BGE query/document 余弦和 BM25 按 0.7/0.3 融合为 st；
Chinese-CLIP 文本 query 对候选图像及局部图像生成 sv/sr。

图片、区域查询：Chinese-CLIP 视觉 query 对候选图像和局部生成 sv/sr，
对同一模型的候选文本生成 st。BGE 与 Chinese-CLIP 虽同为 512 维，也不互相做余弦。
EAFR 仍保留原配置权重、证据覆盖、模态可用性和缺失度，不宣称最优。
真实语料没有独立 CFR/关系标签，sf/sg 不伪造为已知信号。

向量检索在 PostgreSQL 读取通用 pgvector VECTOR，以 Python 精确计算，尚未启用 ANN。
Provider/模型/revision/维度/预处理哈希必须全部匹配。推理服务、模型身份或兼容索引
不满足时返回统一 MODEL_UNAVAILABLE/503，capabilities 如实报告不可用，无静默基线回退。

实际新增95条512维向量：21个图的BGE文本、21个CLIP文本、21个整图区和32个区域视觉。
原74条256维基线向量保留，总计169条，12个真实图和9个合成图均建索引。
重复索引仍169条；业务图、文本、证据、校订和核验记录不修改。

独立PG实测发现初始迁移的实体/模态索引为unique，无法容纳多模型；
新增0002_model_spaces迁移，将唯一约束扩展至完整模型空间。升级不删除已有向量；
降级遇到多模型同实体时拒绝执行，不自动丢数据。

## 两个固定国内古籍案例

入口：[国内古籍演示](http://localhost/demo)。页面从数据库读取四幅真实扫描和来源，
蓝框为AI建议图区、橙框为固定区域查询。固定的是输入及讲解图对，检索排名实时计算。
两种按钮均保存SearchSession，可进入原图/文本与候选/证据页面继续查看。

| 案例 | 原图 / PDF页 | 固定文本输入 | 区域输入 |
| --- | --- | --- | --- |
| gengzhi-loom | 《耕织图》24页室内织机、26页大型织机 | 织机 经线 | 第一幅图的织机/操作者局部，x=.025,y=.35,w=.24,h=.32 |
| tiangong-waterpower | 《天工开物》第2册25页水碓、26页水磨 | 水轮 驱动 谷物 加工 | 第一幅完整机械图区，x=.055,y=.16,w=.9,h=.73 |

《天工开物》为国图数字古籍馆藏，明确归为国内馆藏，未冒充现代出版版本。
具体来源URL、许可和原文件哈希见[国内古籍AI比赛演示](机图索隐_国内古籍AI比赛演示.md)。

- 大型织机：5a0151df-39d7-5076-94e0-5fd18e4bd9bd。

本机实际观察：织机文本查询前两项为室内织机、大型织机，织机局部检索首项为大型织机；
水碓区域检索排除水碓本身后首项为水磨，水碓整图区图片检索前两项为水碓、水磨。
宽泛的“水轮 驱动 谷物 加工”文本查询首项为土礱，水碓、水磨随后；这是当前模型的

据模型分数自动断定功能相同或历史传承。固定图对不是正/负相关性真值。

## 运行与复现

本机模型和索引已准备。仓库根目录执行：

```powershell
.\backend\model_runtime\start.ps1
docker compose -f docker-compose.yml -f docker-compose.ai-real.yml -f docker-compose.neural.yml up --build -d
```

三个Compose文件分别提供业务服务、国内真实扫描只读挂载、神经Provider配置。
切回基线只去掉neural文件，保留ai-real文件，否则已导入扫描会缺挂载。
当前worker监听8767，Docker通过host.docker.internal访问，仅供本机受控演示。
初次安装、模型下载、CPU选项、依赖锁及索引命令见
[模型运行说明](../backend/model_runtime/README.md)。真实资产和权重不进入Git/镜像。

新接口：

```text
GET  /api/v1/demo/cases
POST /api/v1/demo/cases/gengzhi-loom/search         {"mode":"text"}
POST /api/v1/demo/cases/tiangong-waterpower/search  {"mode":"region"}
```

案例未导入时返回明确409，模型/索引不可用时503；错误结构仍为
error.code/message/request_id/details。新增两个操作后OpenAPI共17个V1操作。
