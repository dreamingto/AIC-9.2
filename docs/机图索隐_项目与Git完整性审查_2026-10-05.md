## 发现的问题与处理标准

### P0：最新本地成果没有版本保护，远程缺少当前实现

影响：他人克隆只能获得 9 月 29 日代码；当前工作区不能用远程 commit 代表。单独上传已修改文件也会漏掉 79 个新文件中的关键模块，造成缺导入、缺迁移或缺页面。

下一步：审阅全部修改与新文件、确认 ignore、做内容级秘密扫描，按基础迁移/模型、真实案例、实验工具、文档与测试组织提交。在取得提交/推送授权后同步远程并核对 SHA，冻结一个有明确来源的发布 tag。

验收：最新必需源码/配置/依赖锁全部受版本控制；Git 工作树只有明确的本地产物；远程 SHA 与发布记录一致。权重、原扫描、私密 .env 不纳入源码提交。

### P0：首次启动与真实数据恢复不是完整的复现流程

影响：Compose 声明必需 `.env`，而干净仓库只有 `.env.example`；README 快速启动未给出创建步骤。已在隔离 HEAD 快照复现 `env file ... .env not found`。

真实版另依赖仓库外模型环境/权重和被忽略的 PDF、扫描、supplementary 库存、raw OCR、AI manifest。现有说明要求“恢复输入”，没有可独立取得当前冻结输入的发布清单。页面生成器写当前时间，manifest 指纹包含库存/原始 OCR 等哈希，而固定实验协议严格绑定旧 manifest 名称和 SHA256。因此重新生成的输入可能产生新指纹，不能直接重放当前固定协议；这是来源校验的正常拒绝，需要补发布机制。

下一步：分别形成基础工程、国内真实基线、神经真实版三个明确启动入口；补 `.env.example -> .env`、Python 开发环境安装、模型安装与索引建立；建立独立数据发布清单，明确授权可提供的输入包、哈希、来源 URL、恢复路径及缺文件报错。时间/运行元数据与内容身份如何分离，另做版本化决策，不能覆盖旧锁。

验收：从干净目录和空的独立 PostgreSQL 按文档运行，不借用当前业务卷；能导入 12 图、打开两个案例、建立神经索引、执行 24 查询对照。恢复冻结包时应匹配原指纹；重新生成数据则建立新协议/报告版本，不伪称旧实验的精确复现。

### P0：正式比赛材料与交付包尚未形成

影响：开发文档不能直接替代官方要求的作品技术报告和材料包。当前仓库没有可识别的最终 PDF、视频、答辩材料、简介和发布清单。

下一步：围绕织机和水力加工两个实际案例，整理需求、技术路线、真实模型、EAFR 方法与限制、实际对照、失败案例和下一步；制作技术报告、演示脚本/录屏、答辩材料和代码/数据复现说明。报告同时保留水力重排与整经偏移，所有研究指标继续 not_evaluated。

验收：材料讲述的行为能在冻结版本重放，源码、模型锁、数据锁和报告相互对应，按官方附件核对格式/匿名要求及体积。

### P1：功能/关系证据尚不足以支持完整算法效果主张

影响：线上真实库无功能/关系标签，新实验草稿只覆盖 4/12 图，且没有可靠古文功能引文和独立 qrels。当前报告已观察到整经查询受不均匀草稿覆盖影响而偏向织机。固定查询属于开发集，不能称为独立测试集。

下一步：优先给剩余背景图建立与案例一致的有据 AI 草稿和 unknown 记录，保持 Inferred/confidence=null；建立新版本协议，同时比较 hybrid、功能、证据的消融及反向案例。默认在线策略继续明确展示当前能力；若展示实验草稿重排，使用独立明确的实验模式并完整保存策略版本，不能把实验成绩写成已上线行为。

验收：12 图草稿覆盖和缺失原因都有记录；公开失败案例及不适用查询。按用户当前决定，人工审核不作为本阶段前置条件；无独立真值时不产出 CER/WER/Recall/nDCG。

### P1：区域查询继承整图文字与断言，证据范围不够精确

位置：`backend/app/services/search_service.py` 的 `search_region`，约第 171—194 行。

影响：当前生产路径为局部视觉输入继承整个来源 Figure 的断言、文字主张和关系。若只框水轮，其 query claims 仍可能包含图区另一侧的加工动作。独立实验草稿已经有空间支持裁剪规则，默认服务尚未同步这一规则。

下一步：区分“来源上下文”和“框内可支持主张”；只有可证明落在 crop 范围内的断言/证据参与局部相关性评分，无定位依据的上下文只作展示。不要给純图片输入生成无依据功能。

验收：水轮局部不会继承框外舂捣/谷物加工主张；整图区保留完整可用信息，跨范围/无空间依据用例有回归；新评分行为保留旧会话快照。

### P1：主文档、配置与自动验收仍有缺口

README 仍列 14 个基础接口、旧测试数，并在试点进展中写“业务库仍为 synthetic fixture”。策划/需求文档仍将已接入模型、OCR 和实验列为后续能力；技术文档虽有当前增量说明，下文历史基线与当前实现还需更清楚地分版阅读。

EAFR 权重只支持代码默认/构造注入，Settings 与环境模板没有权重配置，未满足此前“从配置读取”的实现要求。当前缺失模态政策是不重新归一化、贡献不可用时为 0；这是已记录的工程政策，不应在报告中宣称已完成学习或动态可靠性建模。

仓库没有 `.github` 持续检查配置；OpenAPI 与 TS/Zod 仍人工同步；当前通过的检查缺少独立的最终干净目录、浏览器与断网组合验收。

下一步：统一当前状态/历史版本/未来目标；建立权重配置与版本快照；增加依赖锁、静态检查、API 契约和独立 PG 集成 CI，最后对冻结提交跑真实浏览器、故障与断网检查。

验收：当前文档的 API 数、语料规模、模型和指标状态一致；配置信息进入 SearchSession/Candidate；不把组件测试代替全栈测试。
